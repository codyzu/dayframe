# ADR 0007: A separate GeckoView recovery trial for the remaining H6 work

**Status:** staged trial and exact follow-up updates approved on 19 October 2026. Reviewed 0.1.3 is installed; current recovery/normal reboot passed and automatic cold startup is owner-confirmed. H6 is accepted for the approved operational scope after the final owner post-cold Photos/maintenance pass, with cold timing and isolated paint-reset verification limits retained. [Current audit](../hardware/h6-recovery.md#current-requirement-by-requirement-audit) controls actual acceptance; the initial proposal and original artifact description below are historical.

## Why a second package

The owner asked to complete what is possible for H6, preserving prior deferred checks. [ADR 0006](0006-firefox-boot-helper.md)'s helper 0.3.0 already passed physical, hands-off normal/cold startup. It deliberately cannot see Firefox's load, compositor or renderer state. A page timer cannot recover a dead browser process, and periodic blind Firefox launches would interrupt maintenance without proving recovery. The unresolved H6 load/paint/process requirements justify preparing the separately packaged engine shell originally described in the hardware plan.

`hardware/kiosk/` contains independently authored MIT source for `dev.dayframe.kiosk` 0.1.0, code 1, min/target API 23, landscape, ARMv7. It does not copy the accepted Firefox profile, change system WebView, register as HOME, add accessibility, expose URL/JavaScript intent arguments, accept certificate exceptions or install Google account/system services. The accepted Firefox/Rootless/helper setup remains the fallback. A new profile means the read-only display credential must be provisioned normally if the trial is approved; no administrator login belongs in this app.

## Runtime boundaries

- One lazily created Gecko runtime in the main process, with a persistent private `display-profile`. Application startup and the separate supervisor do not initialize Gecko. Require a plausible October-2026-or-later clock stable for ten seconds before runtime/profile creation. Use an internal config path rather than Gecko's default `/data/local/tmp` override. Remote debugging, console output, about:config and login autofill are disabled.
- The public configured address must be exactly `https://host/?display=frame`. Only root display and `/setup` on that origin may become top-level documents. Deny other schemes, origin changes, credentials/fragments/query keys, administration paths, popups and subframes. Intent URLs/actions do not configure the app. HTTPS certificate failure blocks automatic recovery; correcting the clock or an explicit retry can try again without any validation bypass.
- Complete navigation using `onPageStop(success)` plus a subsequent ready signal from a bundled isolated content script. First contentful paint alone cannot finish a load. The probe reports only a mode-independent DOM/clock/animation-frame readiness boolean and the existing French private-access-denial state; it never reads inputs, tokens, cookies, photos or response bodies. Native reception checks extension ID, content-script environment, top-level sender, current session and configured URL. It accepts state signals only, not native commands.
- One monotonic recovery state machine: 45-second load timeout, 25-second missing-heartbeat limit, 15-second persistent paint-loss/readiness-loss limit; retry jitter starts at 5–6 seconds and caps at 60 seconds. A connection restoration expedites an existing retry rather than reloading healthy offline content. Close replaced sessions. Recreate a session for renderer death/stall, with at most six replacements per hour before a native manual-recovery state. Authentication denial stops automatic reloads for provisioning.
- A separate `:supervisor` foreground service receives main-UI-thread heartbeats through a private Messenger. With explicit opt-in and overlay consent, a 30-second missing heartbeat can kill only a freshly verified same-UID **main app process** and launch the kiosk. It never targets Firefox, Android or an arbitrary supplied PID. Allow at most three restarts per hour, persist the budget across service recreation, and reset it only on the protected boot broadcast/new window. Pause supervision when leaving intentionally for maintenance/settings; no repeated foreground takeover loop. Android force-stop stops the whole package and still needs a manual launcher/ADB fallback.
- A native DK button and a stationary two-finger hold open maintenance independently of page JavaScript. The supervisor has a service-owned DK overlay/dialog outside the app and independent of the main UI process. Configuration, boot and supervision are off until normal UI opt-in. Flag files avoid cross-process SharedPreferences caching races. Private atomic `health.json` stores only PID, session generation, state, foreground/maintenance booleans and monotonic timing, for acceptance evidence. It contains no household page data or URL.

These are source/host-tested properties. Actual Android lifecycle, rendering, touch, memory, session/cookie persistence and recovery remain device acceptance gates. The gesture and Settings route must pass physically before disruptive tests or switching startup. Default permission delegates deny unused web capabilities. The app requests Internet, network state, boot reception, overlay and the engine's normal wake lock; the AndroidX private signature permission is retained. Runtime phone/storage/camera/microphone/location permissions and root/settings-write permissions are absent.

Official `org.mozilla.geckoview:geckoview:143.0.20251003115653` exists.
