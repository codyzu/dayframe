# ADR 0006: Reuse Firefox for the first H6 startup slice

**Status:** Accepted for the exact app/boot trial on 18 October 2026. Owner approved helper 0.3.0 installation/configuration, fullscreen/DF checks, one normal reboot and one owner-operated cold power cycle. Hands-off normal-reboot startup passed remotely and the owner confirmed **Yes, no taps needed**. A final untouched cold cycle also passed actual-frame observation and owner confirmation (**Yes, it worked by not touching it!**). The bounded startup slice is accepted; broader H6 recovery remains open.

The owner requested H6 so Dayframe starts automatically after a power cycle, preserving all earlier skipped checks as deferred. H5 already accepted fullscreen Firefox and cold-cycle private-photo persistence. Its remaining startup gaps are the Home chooser and missing DF overlay. A new GeckoView profile and engine are unnecessary for this bounded slice; the full H6 failure-recovery scope remains open.

Extend the independently authored MIT maintenance helper to 0.3.0, retaining Firefox 143.0.4, its existing profile, accepted cookie-cap preference, Rootless shortcut and stock Home. Add only Android's normal `RECEIVE_BOOT_COMPLETED` and `ACCESS_NETWORK_STATE` permissions to the existing overlay permission. No native web engine, root calls, HOME registration, launcher preference change, accessibility, Internet permission or system modification.

Startup is disabled until configured through the helper's normal UI with a public HTTPS root address and exactly `?display=frame`. Reject user info, other paths, ports, fragments and additional query parameters. Store only that address and the enable flag privately; never pass a key or inspect Firefox data. Launch the exact installed shortcut contract: `mozilla.components.feature.pwa.PWA_LAUNCHER`, explicit Firefox `mozilla.components.feature.pwa.WebAppLauncherActivity`, document/new-task flags. This contract is pinned to the measured Firefox and must be rechecked after browser upgrades.

On the protected Android boot broadcast, an enabled API 23 helper restores DF using its existing grant and starts one bounded foreground-service job. Wait at least 20 seconds for vendor startup, a plausible wall clock (1 October 2026 through 2099) and ten continuous seconds with a connected default network. Poll every two seconds using monotonic elapsed time and stop after ten minutes. The date check is a heuristic, not proof of accurate time or usable Internet; Firefox retains TLS validation. Launch once, without a repeated foreground-takeover loop. Opening maintenance, disabling startup or stopping the service cancels pending navigation. Boot startup does not resume after Android force-stop until manual app launch; there is no browser/process watchdog. Missing permissions, a changed Firefox shortcut or late/unusable Internet can require manual recovery.

H5 showed Firefox's own WorkManager boot receiver starting before clock correction. This helper cannot prevent that early profile access. The separately accepted cookie-cap preference remains relevant; delaying our launch does not supersede its evidence or undo.
