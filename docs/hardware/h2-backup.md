## Completed offline structure review

The independently matching 1 MiB header samples contain a DOS MBR signature, not a GPT header or an assumed Allwinner partition table. Primary entry 3 is an extended-partition container; its kernel-exposed 1 KiB node is consistent with Linux’s deliberate small extended-container mapping, rather than an unexplained data partition. The final decode of 13 MBR/EBR records accounts for all 15 exposed partition nodes and reconciles their actual ranges against the private storage map.

The MBR’s userdata entry extends **48 MiB beyond the measured device capacity**. The H1/H2 sysfs userdata length instead ends exactly at the measured device boundary. This is consistent with [Linux’s partition boundary clipping](https://github.com/torvalds/linux/blob/v3.4/block/partition-generic.c) and [extended-container mapping](https://github.com/torvalds/linux/blob/v3.4/block/partitions/msdos.c); the exact vendor kernel implementation has not been audited. Preserve the original table in the capture, record advertised versus exposed lengths privately, and never repair or extend it as part of backup. This does not establish a safe restore layout. The declared extended-container range also overlaps the primary bootloader range and ends before some logical ranges. The kernel exposes the container as a small metadata node, and the actual exposed data partitions remain non-overlapping and within physical capacity. These original declarations are preserved as observed; they are not a validated restore layout. Final header/image comparisons and repeated table analysis passed with these original anomalies explicitly recorded. Offline signature and filesystem-bound checks passed; whole-filesystem consistency is not established.
