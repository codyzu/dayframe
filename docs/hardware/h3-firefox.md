### Owner-approved network recovery restart — 17 October 2026

The old frame address stopped responding to ping and TCP 5555, and the owner confirmed the router listed the frame as disconnected. The Mac’s public health request received HTTP 403; that result does not establish a general Mac internet outage. The owner inspected the physical Power menu, confirmed Restart/Reboot was offered, then explicitly approved and performed **one normal restart**. The agent issued no device reboot command and no further restart is authorized by this approval.

After boot, the owner reported stock photo-frame Home/Settings rather than Firefox. Wi-Fi reconnected at the same owner-confirmed private address. TCP 5555 became reachable; the first ADB connection was offline. A target-specific host `adb disconnect` followed by `adb connect` recovered the transport. Classic model/firmware/API/ABI matched again, the shell remains `uid=0(root)`, and Firefox 143.0.4 / code 2016118128 remains installed. Raw recovery/identity/window evidence stays in ignored `diagnostics/h3/`. This is one observed recovery boot, not boot-to-kiosk or repeated stability acceptance.

Read-only stock-screen inspection found a StatusBar window with zero height and no navigation-bar window/controller. No relevant navigation toggle was found in the inspected runtime properties/settings; this is not proof no vendor mechanism exists. Settings navigation over ADB is inspection evidence, not a successful physical Firefox round trip.
